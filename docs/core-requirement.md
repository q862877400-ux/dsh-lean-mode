# 对核心诉求的直接回答

## 诉求

```
R1（硬）  1000+ 工具时，能【准确】调用工具
R2（硬）  不影响 AGENTS.md 的遵循度
R3（软）  在不影响 R1 的前提下，省一点上下文
```

---

## 结论

### R2 怎么满足：★ 指令区【一个字都不放工具内容】

工具 schema 走的是**请求的 tools 字段**，**本来就不进 AGENTS.md** ✓
⇒ ★★ **只要不往指令区塞工具清单，R2 自动满足。**
⇒ ✗ **目录（无论名字还是带描述）就是往指令区塞东西 ⇒ 直接违反 R2。**
⇒ ✗ **我发明的 `index` 档（+11.3 KB 索引）违反 R2**，出局。
⇒ ✗ **lean 的目录部分也违反 R2**，出局。

### R1 怎么满足：★ 通道里给【全量 schema】

参数信息必须完整抵达模型，模型才能填对参数。
⇒ ✗ **任何砍 schema 的做法都在牺牲 R1** ⇒ **lean 的 `shape: true` 出局**。

### R1 的真正瓶颈：不是「怎么呈现」，是「1000 个全发出去本身」

我实测：**731 个肥工具 = 275k token（100 万窗口的 27.5%）**。1000+ 只会更多。
⇒ ★★ **如果 R1 是硬指标，「减 N」（按需挂载）才是唯一稳的路** ——
   它改的是**挂多少**，不是**怎么写**。

### R3 怎么满足（且不碰 R1）：换紧凑编码

★ 实测上限：同一份信息，**JSON Schema 814 B/工具 vs TS 投影 719 B/工具 = 省 11.7%**。
（官方 `ts-types.ts` 自述：两者是 *two projections of the same store*）
⇒ ★ **这是「不丢信息」能省的量级 —— 就 10% 出头，不是 60%。**

---

## 所以该怎么做（一句话）

```
指令区：不放任何工具内容          ⇒ 满足 R2（硬规矩）
通道  ：全量 schema               ⇒ 满足 R1
减 N  ：1000+ 工具按需分组挂载    ⇒ 满足 R1 的前提（装得下才谈得上准）
省一点：换紧凑编码 + 删描述冗余    ⇒ 满足 R3（约 10%）
```

### 明确出局的

| 做法 | 为什么出局 |
|---|---|
| **lean 的砍 schema** | 牺牲 R1（实测端到端 **89.9% vs 95.0%**） |
| **任何形式的目录/索引** | 违反 R2（往指令区塞东西） |
| **PTC** | ★ 它的 SDK 段**同样是 O(N)、719 B/工具**，解决不了装不下的问题；它解决的是**批量调用** |

---

## 一句话总结

> **你要的东西 = 指令区零污染 + 通道全量 + 按需减 N + 紧凑编码。**
> **「lean 模式」不在其中** —— 它买的是上下文，付的是 R1，而 R1 是你的硬指标。
